04 / MECHANISM LAB

负载没变，为什么还是扛不住？

三个可手算的教学模型，帮助理解工作量、重试和故障余量。所有输入均为假设，不代表 DeepSeek 实测容量，也不能据此估算某型号 GPU 数量。

05 / OBSERVABILITY

把“服务正常”，写成可检查的条件。

下面是建议的观测语义，不是 DeepSeek 内部实际指标名。阈值要根据任务、工作量和压测确定；没有适用于所有模型的通用百分比。

最小诊断上下文

稳定匿名租户、模型/别名与可见版本、模板/适配器版本、输入/输出/缓存计数、阶段时间、重试序号、终态分类、工具业务状态。高基数请求 ID 放 trace 或受控日志；API key、原始提示词、思考内容和工具敏感参数不进普通指标。

06 / RESTORE & PREVENT

先切断放大，再恢复最小故障域。

一次恢复至少有四个目标：新请求能完成、在途结果有明确状态、业务副作用可核对、孤儿计算与计量缺口可收敛。各自设验收，不相互替代。

让演练证明退路存在。

在已授权的隔离环境验证下列场景。本网页不执行故障注入，不连接任何集群。

从零建设：按证据和恢复能力排序。

这里的 P0 / P1 / P2 是建设优先级建议，不是对某次事故的定级。
