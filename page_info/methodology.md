# 研究方法与证据边界

日期：2026-11-05，Asia/Shanghai。

## 研究问题

本研究围绕五个连续问题组织：请求如何经过平台；哪个资源或状态可能失效；用户看见什么；什么证据可以排除其他原因；如何有边界地恢复并证明预防有效。

研究以平台 SRE 视角为主，同时区分调用方能控制的边界：并发、期限、重试、协议解析、任务验收和业务幂等。未公开的生产权限、配置及命令不予虚构。

## 资料路线

并行核查三组独立资料，再交叉审阅：

1. DeepSeek 官方代码与部署披露：DeepInfer、固定版本部署 Q&A、历史 V3/R1、DeepEP、EPLB、FlashMLA、DeepGEMM、3FS、Recipe。DualPipe 单列为训练边界。
2. DeepSeek 官方 API 契约与状态事件：并发、错误、缓存、Chat/Responses、思考工具协议、更新记录与公开状态页。
3. 原始论文及其他官方参考实现：DistServe、PagedAttention、vLLM、SGLang、NVIDIA Dynamo、NCCL、Google SRE。

来源登记在 `sources.json`；每项给出能支持什么、不能据此推断什么。网页引用能定位来源，处置卡标记为工程推演，而非将参考软件伪装成 DeepSeek 内部实现。

## 证据分层

| 类别 | 可以表达 | 不可直接外推 |
| --- | --- | --- |
| 官方部署披露 | 特定版本、硬件路径与机制 | 全公司、全模型、所有地域当前状态 |
| API 契约 | 公开输入输出与行为边界 | 未承诺的无损续写、持久会话或业务恰好一次 |
| 历史快照 | 当时设计、硬件与观测 | 当前吞吐、成本、可用性或 SLA |
| 官方软件 / 参考实现 | 组件能力与具体版本限制 | 已在线采用或对所有任务默认开启 |
| 公开事件 | 披露的影响、时间和恢复更新 | 未公开的内部技术根因 |
| 工程推演 | 条件性的故障机制与处置建议 | 已发生事故、真实概率、未经验证的恢复保证 |

## 交互图与公式的含义

架构全景是逻辑职责、请求路径和状态依赖图，不是数据中心或网络物理拓扑。橙色通用职责明确标记为未公开内部实现。条件分支不会被画成所有请求必经阶段。

故障全景是可能的传播机制；灰化只代表当前未选中的路径。切断反馈不会自动修复源故障，也不意味着零损失恢复。故障触点矩阵的圆点用于导航诊断，不是已确认因果归属。

工作量模型、Little 定律、有界重试和 N−1 规划公式均标明假设与单位。没有据此预测 DeepSeek 实际 GPU 数、容量、恢复时长或故障概率。失败相关性、缓存状态、长尾和共同依赖会使简单线性/独立模型偏乐观。

## 内容复核时修正的边界

- 当前 Prefill 不采用前缀亲和路由；参考框架的亲和热点不能移植成 DeepSeek 事实。
- Block 与 SWA 丢失的恢复成本不同；不能全部假定为完整上下文重算。
- 当前披露的 Decode 没有缓存容量瓶颈；KV 抢占/容量卡适用于参考实现、自建配置与异常状态风险。
- Engram 的 GPU 主机/RDMA 路径与 NPU 设备内存路径不能混用。
- 图片视觉编码与结构化输出编译作为条件分支补齐。
- 投机自适应策略已有披露；未知的是完整生产实现与部署参数，不能笼统称算法未公开。
- 工具幂等按每个预定动作 ID，而非把整个多动作任务压成只准一个动作。
- 两个延迟达标率不能相加，联合达标率使用同一合格原始请求分母。

## 未覆盖的实证与后续工作

本研究没有 DeepSeek 内部 trace、真实故障日志、容量曲线、值班手册、私有拓扑、计费数据库设计或实际演练结果。公开事件没有技术 RCA 时保持未知。

因此不能给出厂商内部故障频率排名、真实恢复时长分布、现有防护成熟度评分或生产参数建议。若日后获得授权的真实证据，应优先用阶段时间、完整实例容量、事件/版本关联及业务动作状态验证这里的候选机制，再更新故障库。
