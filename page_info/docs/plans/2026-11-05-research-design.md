# DeepSeek API 稳定性研究台：设计

研究日期：2026-11-05，Asia/Shanghai。

用户已明确授权完整研究、页面实现及本目录内的交付。视觉、技术栈和内容组织采用以下默认选择，持续完成研究和交付。

## 目标与边界

面向熟悉服务端稳定性的读者，建立 DeepSeek API 请求生命周期、分布式推理资源及典型事故之间的可解释联系。每个故障条目必须回答：表现、候选原因、如何证伪、立即止损、恢复步骤、恢复验收、预防、危险操作。

官方 API 契约、官方部署披露、历史实现、其他项目参考能力、作者建议分开标注。状态事件只引用已公开影响和时间；未公开技术根因时不得补写。不开通账户、不发送真实推理请求、不接触生产系统。

## 方案选择

1. 长篇图文报告：便于顺序阅读，但症状与组件之间跳转较差。
2. 仿监控大盘：便于看数，但缺少真实线上数据，容易制造错误确定性。
3. 单页研究台（采用）：一条可点击请求链路、一个可筛选故障库、几个明确标注假设的交互实验，附可追溯来源与完整文字稿。

## 内容结构

1. 研究摘要、版本边界、核心判断和阅读入口。
2. 交互架构：接入、协议、安全、调度、缓存、Prefill、传输、Decode、专家与 GPU、控制面。
3. 请求生命周期：正常、排队、缓存失效、输出停顿、流中断、取消失效。
4. 故障库：按症状、层级、关键词筛选；每项可直接定位并展开完整处置。
5. 机制实验：Little's law、缓存计算量、重试放大、N-1 容量。
6. 观测与 SLO：完成语义、延迟分段、资源与因果证据。
7. 恢复与预防：处置顺序、故障演练、发布和长期建设。
8. 来源与证据：主张台账、官方事件、适用范围及未公开项。

## 视觉与技术

中文编辑式研究档案；暖白底、深蓝文字、橙色强调、青绿证据色。固定侧边目录，正文保留宽裕行距。复杂结构使用 HTML/SVG，避免依赖外部图表库。

纯 HTML/CSS/JavaScript，编译为可直接双击打开的 `index.html`。不依赖网络、CDN、Node 服务或框架。源文件保留在 `src/` 便于修改。外部来源链接仅在读者主动点击时打开。

## 验证

先测试交互计算的数学边界与手算样例，再实现核心函数。使用真实 Chromium 验证搜索、筛选、故障跳转、架构选择、生命周期切换、计算器、键盘导航、移动布局和离线文件打开。核对全部来源引用有效、证据类别完整、所有故障有恢复与验收。截图用于目视检查。
